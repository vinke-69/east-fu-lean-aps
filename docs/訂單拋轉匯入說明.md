# 訂單拋轉匯入

新增「訂單拋轉＋資料庫」資料來源，保留原排程 Excel 與範例模式。

## 操作步驟

1. 選擇「訂單拋轉＋資料庫」，上傳機台產能與模具規格資料庫（支援 `.xls`、`.xlsx`）。
2. 上傳一份或多份訂單拋轉 Excel。檔案必須有「單頭資料」，以及含「結關YYYY.MM.DD」的檔名。
3. 查看已顯示的規格、結關日、生產完成日及急迫程度。修改急迫程度後，按「保存急迫程度修改」。可下載解除規格欄隱藏的原檔副本，不覆寫本機原檔。
4. 第一次使用某個產品／規格時，核對品名與用途，為各可用機台選擇產速及模具來源，按「確認並保存此產品對應」。近似品名僅排序候選，不自動代替使用者決定。產品確實不適用時，可明確勾選「無符合機台」。
5. 下載已確認對應檔。下次上傳相同兩份資料庫後，載入對應檔並按「套用對應檔」，即可沿用。資料庫內容變更後會拒絕舊對應，須重新核對。
6. 問題比例低於 30% 時，按「完成匯入，套用至排程」，確認下方排程期間，再按「確認設定並開始排程」。問題工單仍出現在未排清單、KPI、策略比較與結果 Excel。達 30% 時整批停止，先處理缺漏。

## 已確認的計算規則

- 結關日為交貨日；生產完成日往前推 3 個平日，跳過週六、週日。此倒推規則未扣除國定假日。排程的「交期」採生產完成日當天 23:59:59，另保留結關日供查核。
- 急單按本次上傳所有工單數的 10% 向上取整，依結關日由早到晚排序，同一邊界日期全部列入。整批同一天時全部預設為急單，可手動修改。
- PC 與 PCS 同義。一件是規格所列長度的一卷／一條；1 FT = 0.3048 M。每小時件數 = 實際產速（M/分）×60÷每件長度（M）。不計包裝、裁切。
- 僅使用 C2、C4、C5；一筆工單只指派一台機台，不拆單。
- 備用機台須有該產品在該機台的個別實際產速，不沿用主機台產速，不採拖台產速。
- 規格換算為 mm，以小數點後兩位四捨五入比較。產能採內、外徑；模具採成品內徑、厚度。長度不影響換模群組；同產線同內徑、厚度不換模，其餘沿用既有預設換模時間。
- 每筆問題工單只計入比例一次，即使有多個問題。「無符合機台」、缺料、未確認對應、重複工單均計入；空白行不計。
- 原排程設定仍决定排程起迄、可用機台、停機與產能比例。生產完成日倒推與「週末不排程」是分別設定；不因交期規則而自行更改工廠工作日曆。

## 防呆與追查

- 保留來源檔名、工作表、列號、原規格、產速及模具來源。
- 不以 SKU 單独決定產品；不同規格不得共用對應。同品號但品名或規格不同會分別確認。
- 多份訂單的重複製令單號全部列為問題，不自行刪除版本。
- 無效檔名日期、錯誤工作表或無法識別的資料庫格式会顯示錯誤，不能沿用前一次結果。
- 更換訂單／資料庫、保存優先級或產品對應時清除舊排程，須重新套用及計算。
- 同列多生產機台僅一個產速、內外管分段製程等資料會列出待確認原因，不自動推論完整產速。
- 缺少管徑、尺寸不符、無個別機台產速或無相符模具時，需補齊原資料庫／訂單或確認不適用。

## 暫存與正式使用

資料庫及產品對應保留於目前 Streamlit 工作階段，不寫入公開 GitHub。關閉／重連後可能需重新上傳；請自行下載對應檔。尚未串接私人雲端或新增使用者權限模組。

既有「歷史排程」仍依原系統運作，並非私人帳號隔離空間；本次未改動其共用方式。正式使用前應依需求加入私人儲存及存取控制。

## 程式變更

- `aps/import_orders.py`：訂單讀取、來源追查、解除規格隱藏副本、基本缺漏與門檻判斷。
- `aps/import_dates.py`：平日倒推與急單預設。
- `aps/import_catalog.py`：兩種 Excel 讀取、實際合併儲存格還原、管徑換算與候選資料。
- `aps/import_rates.py`：個別機台實際產速查核工具。
- `aps/import_pipeline.py`：已確認對應的檢查、件數產速換算、匯入未排工單及排程結果整合。
- `ui/order_import.py`、`app.py`：上傳、急單修改、對應確認／保存、缺漏顯示與排程串接。
- `aps/parser.py`、`aps/validator.py`、`aps/scheduler.py`：保留匯入追查資料，門檻防呆，讓未排工單進入既有報表與比較。
- `requirements.txt`：加入讀取舊式 `.xls` 所需的 `xlrd`。

測試使用合成資料驗證邊界，不將工廠原始訂單、產能、模具或真實對應檔提交到公開倉庫。
